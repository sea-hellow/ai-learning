## 总览

草稿里共 **16 处**问题，分成三类。**分类的标准是"编辑器的红波浪线能不能抓到"**：

| 类别 | 处数 | 编辑器能抓吗 | 你当时怎么发现并改对的 |
|---|---|---|---|
| A · 语法/拼写错误 | 13 | ✅ 能（红波浪线 + 悬停提示） | 靠提示改的 |

## A 类 · 语法/拼写错误（13 处）

这类错编辑器会立刻标出来，你靠悬停提示改对了。**这个用法完全正确，专业程序员也这么干。**

### A1 · 引号不匹配（3 处）

| 行 | 草稿写的 | 问题 | 正确写法 |
|---|---|---|---|
| 15 | `print(f"{temps})` | `}` 后面是 `)`，引号没闭合 | `print(f"{temps}")` |
| 25 | `print(f"{temps})` | 同上 | `print(f"{temps}")` |
| 27 | `print(f"{temps})` | 同上 | `print(f"{temps}")` |

**报错长这样**：`SyntaxError: unterminated string literal`
**规律**：f-string 是 `f"..."`，**函数调用是 `print(...)`** —— 括号在外层，引号在内层。你写反了层次。

### A2 · 缺冒号（9 处）

| 行 | 草稿写的 | 正确写法 |
|---|---|---|
| 30 | `if t>=35` | `if t>=35:` |
| 32 | `elif t>=30` | `elif t>=30:` |
| 34 | `elif t>=20` | `elif t>=20:` |
| 36 | `elif t>=10` | `elif t>=10:` |
| 38 | `else` | `else:` |
| 47 | `for s in scores` | `for s in scores:` |
| 49 | `if s>highest` | `if s>highest:` |
| 51 | `if s>=60` | `if s>=60:` |
| 53 | `if s>=90` | `if s>=90:` |

**报错长这样**：`SyntaxError: expected ':'`
**规律**：**凡是 "if / elif / else / for / while" 开头的行，结尾一律要冒号**，没有例外。

### A3 · 函数名拼错（1 处）

| 行 | 草稿写的 | 正确写法 |
|---|---|---|
| 24 | `temps.attend(28)` | `temps.append(28)` |

**报错长这样**：`AttributeError: 'list' object has no attribute 'attend'`
**规律**：`append`（追加）。Python 会告诉你"列表没有 attend 这个方法"，顺着提示换成 append 就行。

## B 类 · 概念混淆（2 处）

这两处编辑器能报错，但**报错信息不会直接告诉你原因**，得自己想明白。

### B1 · `len.temps` —— 括号写成了点号（第 18 行）

| 草稿写的 | 正确写法 |
|---|---|
| `a=len.temps` | `a=len(temps)` |

**报错长这样**：`AttributeError: 'builtin_function_or_method' object has no attribute 'temps'`
（翻译：`len` 是一个函数，它没有叫 `temps` 的属性 —— 但你想要的是"把 temps 交给 len 去数"）

**这是第 4 周手册专门讲过的区别，说明当时还没完全内化。再记一遍：**

```python
len(temps)          # ← 通用工具（len / sum / max / min）
                    #   把东西放在「括号里」

temps.append(28)    # ← 列表自己的方法
s.strip()           # ← 字符串自己的方法
                    #   这些用「点号」，点号后面跟方法名
```

**判断口诀**：
- **谁拥有这个能力？** 列表自己有 append → 用点号：`temps.append()`
- **还是通用工具？** len/sum/max 谁都能用 → 用括号：`len(temps)`

### B2 · `all = 0` —— 用了 Python 内置名（第 14 行）

```python
all=0        # ← 草稿里写了，但后面没用上
```

`all` 是 Python **内置函数**（用来判断"是否全部为真"）。拿它当变量名**不会报错**，但会**悄悄覆盖掉内置功能** —— 以后想用真正的 `all()` 就会出莫名其妙的错。

**这已经是第二次了**（第 4 周用了 `file`）。

**处理办法**：加个前缀或换描述性名字。

```python
calc_all = 0      # 加前缀
total = 0         # 或者用描述性名字（推荐）
```

## C 类 · 逻辑错误（2 处）★★ 编辑器抓不到

**这两处语法完全合法 —— 不报错、不警告、红波浪线不会出现。** 只能靠"跑起来看结果"或"手工验证"发现。

### C1 · 复制粘贴忘改文字（第 37 行）

```python
elif t>=10:
    print("酷热")      ← ★ 应该是 "微凉"
```

**这行所有语法都对**：冒号有、缩进对、括号闭合、引号成对。所以编辑器**一个字都不会说**。

但真跑起来，t=15 会输出"酷热" —— 结果完全错误。

**成因**：从上面几档复制过来忘了改文字。**写重复结构的分支时，这是最容易犯的错。**

### C2 · 求平均用了整除 `//`（第 23 行）

```python
b=sum(temps)
print(b//a)          ← ★ 应该是 b/a
```

**15÷5=3（能整除）时看不出问题** —— 得 `23`，看起来和 `23.0` 差不多。

但换成 `[23,19,31,27,16]`（和 = 116）立刻暴露：

```
116 / 5  = 23.2    ← 正确
116 // 5 = 23      ← 少算了 0.2
```

**规律**：**求平均、求比例必须用 `/`**；`//` 只用在"能完整装几个"的场合（比如算几天、几箱、几页）。

## ★ 给未来的自己：编辑器盲区的三个自查动作

红波浪线清干净 ≠ 代码正确。**代码写完后，多做这三件事：**

### ① 换一组数据再跑一次

```
[23, 19, 31, 27, 15]  →  [23, 19, 31, 27, 16]
平均分 23（看不出问题）→ 平均分 23.2（`//` 的 bug 立刻暴露）
```

**原理**：有些 bug 只在特定数据下显形。**换数据是最便宜的检验手段。**

### ② 回算验证

算完"1 天 3 小时 26 分 5 秒"，倒着算一遍：

```
1×86400 + 3×3600 + 26×60 + 5 = 98765  ← 等于原数，说明算对了
```

**原理**：正着算容易带错，倒着算能发现"哪一层没扣掉"。

### ③ 边界值测试

分级判断（if/elif）一定要测**边界上下各一个值**：

```
t = 35 / 34   ← 35 应进"酷热"，34 应进"炎热"
t = 30 / 29
t = 20 / 19
t = 10 / 9
```

**原理**：`>=` 和 `>` 写错、顺序排错，都只在边界处显形。中间值（比如 t=28）永远是对的，测了也没用。

## 一句话总结

| 问题类型 | 谁来发现 |
|---|---|
| 拼写、标点、缺冒号 | **编辑器**（红波浪线） |
| 括号还是点号、内置名 | 编辑器报错 + **自己理解原因** |
| **逻辑错、边界错、运算符选错** | **只有你自己** —— 靠换数据 / 回算 / 边界测试 |

**把"跑起来看一看"变成固定动作，这一类错误就抓得住了。**
